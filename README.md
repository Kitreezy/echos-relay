# echos-relay

Вебсокет-релей для [echos](https://github.com/Kitreezy/echos).

Приложение умеет общаться напрямую через MultipeerConnectivity, но только с
устройствами, которые рядом. Релей нужен, чтобы связь работала из разных сетей:
клиенты подключаются к нему, а он пересылает кадры между ними.

Хранилища нет. Ни истории, ни аккаунтов, ни базы — всё состояние это список
тех, кто сейчас на связи, и живёт он в памяти процесса. Перезапустили сервер —
клиенты переподключились и представились заново.

## Запуск

```
go run .
```

Слушает `:8080`, вебсокет на `/ws`, проверка живости на `/health`.

Клиенту адрес задаётся через `UserDefaults`, поэтому для запуска из Xcode
достаточно добавить в схему аргумент:

```
-echos_relay_url ws://<имя-мака>.local:8080/ws
```

Имя мака смотрится через `scutil --get LocalHostName`. Устройство и мак должны
быть в одной Wi-Fi. При первом подключении iOS спросит разрешение на локальную
сеть — без него соединение молча не установится.

## Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `PORT` | `8080` | Порт |
| `PING_INTERVAL_SEC` | `20` | Как часто сервер пингует клиента |
| `PONG_TIMEOUT_SEC` | `10` | Сколько ждать ответа, прежде чем закрыть |
| `MAX_MESSAGE_KB` | `64` | Потолок на входящий кадр |
| `AUTH_TIMEOUT_SEC` | `10` | Сколько ждать `hello` с подписью |

## Протокол

По сокету ходит один тип объекта — конверт:

```json
{ "kind": "message", "sender": "9f86d081884c7d65", "recipient": "2c26b46b68ffc68f",
  "payload": "<base64>" }
```

`sender` и `recipient` — отпечатки ключей, а не имена. Имя ходит отдельно, в
списке присутствия.

`payload` сервер не разбирает: внутри лежит вложенный JSON, который понимает
только клиент. Go кодирует `[]byte` в base64 так же, как `JSONEncoder` в Swift
кодирует `Data`, поэтому форматы сходятся без дополнительных договорённостей.

Виды конвертов:

- `challenge` — случайная строка от сервера. Уходит первой, сразу после
  установки соединения.
- `hello` — клиент представляется: имя в `sender`, открытый ключ и подпись под
  вызовом в `payload`. Присылается при **каждом** подключении: после реконнекта
  сервер о клиенте ничего не помнит. Пока клиент не представился, его конверты
  не пересылаются.
- `presence` — кто сейчас в комнате: пары «отпечаток, имя», по отпечатку.
  Только от сервера.
- `message`, `typing`, `stroke` — пересылаются дальше. Если задан `recipient`,
  конверт уходит тому, чей это отпечаток, иначе всем, кроме отправителя.
- `wallRequest` — просьба прислать стену целиком, `wallState` — ответ на неё.
  Оба адресные. Нужны потому, что росчерк, отправленный отсутствующему,
  пропадает: очередей в памяти релея нет. Владелец стены — источник правды, и
  открывая её, собеседники спрашивают у него напрямую.

Поле `sender` во входящем конверте сервер игнорирует и подставляет отпечаток
ключа, которым клиент подтвердил подключение: написать в конверте можно что
угодно.

## Кто есть кто

Аккаунтов в приложении нет, но личность и не обязана приходить снаружи.
Устройство при первом запуске заводит пару ключей Ed25519 и держит закрытую
часть в Keychain. Отпечаток открытой части и есть адрес, по которому этому
человеку пишут.

Порядок такой: сервер на каждое соединение выдаёт свою случайную строку,
клиент подписывает её и присылает вместе с открытым ключом, сервер проверяет
подпись и считает отпечаток. Строка одноразовая, поэтому подслушанная подпись
годится ровно для того подключения, в котором её сделали.

Имя при этом не значит ничего. Его никто не проверяет и не резервирует: назваться
Bob может кто угодно, хоть все сразу. Смысла в этом нет — конверт уходит по
отпечатку, и самозванец получит только то, что адресовано его собственному
ключу. Имя нужно, чтобы человек узнал собеседника в списке, и живёт оно в
присутствии рядом с отпечатком.

Так честнее, чем сторожить имена. Реестр имён пришлось бы хранить, он не
пережил бы перезапуск, и на бесплатном тарифе, где сервис засыпает, имена
освобождались бы каждые несколько часов. С отпечатком хранить нечего: адрес
выводится из ключа заново при каждом подключении.

Чего это не даёт: понять, что «Bob» в списке — тот самый Bob. Отпечаток
уникален, но человеку он ни о чём не говорит. Узнавать собеседника по адресу
должен клиент — запоминать, с кем уже разговаривал, и показывать нового
однофамильца как нового человека.

## Чего здесь нет

- **Комнат.** Комната одна на всех. Когда понадобятся отдельные чаты, имя
  переедет в путь запроса.
- **Масштабирования.** Присутствие лежит в памяти, значит инстанс должен быть
  один. Для второго понадобится Redis, иначе половина собеседников не увидит
  другую.

## Собеседник для проверки

Почти всё в echos проверяется вдвоём, а второго телефона под рукой обычно нет:
у бесплатного аккаунта разработчика три устройства на год, и тратить их на
проверку переписки жалко. Поэтому вторым участником может быть программа.

```
go run ./cmd/peer -name Борис
```

Подключается к релею как обычный клиент — рукопожатие, присутствие, всё
настоящее. С точки зрения приложения это живой человек: по проводу отличить
нельзя. Дальше команды со стдина, `?` покажет список:

```
who            кто в комнате
to <имя>       выбрать собеседника
say <текст>    написать выбранному
typing on|off  показать, что печатаете
draw           нарисовать росчерк на стене выбранного
wall           попросить у выбранного его стену
mywall         что нарисовали на вашей стене
```

Ключ выводится из имени, поэтому «Борис» после перезапуска остаётся тем же
человеком — иначе приложение считало бы его новым знакомым при каждом запуске.
Чтобы изобразить как раз тёзку, а не старого знакомого, есть `-fresh`: имя то
же, ключ другой. Так проверяется, что приложение отличает одного от другого.

Адрес задаётся через `-url`, в том числе боевой:

```
go run ./cmd/peer -name Борис -url wss://echos-relay.onrender.com/ws
```

## Деплой

`Containerfile` собирает статический бинарь на alpine. На Render — Web Service
из этого репозитория, окружение Docker, порт `8080`.

На бесплатном тарифе сервис засыпает после простоя, и вебсокеты при этом
рвутся. Для echos это скорее плюс: переподключение с откатом получает
проверку в бою.

## Тесты

```
go test ./...
```

Поднимают релей на случайном порту и гоняют через него настоящие соединения:
присутствие, пересылка, адресная доставка, подмена отправителя, игнор
непредставившихся, обновление списка при уходе. Про рукопожатие — что без
подписи не пускают, что подпись из чужого вызова не годится, что адрес
остаётся тем же после реконнекта и что молчащее соединение закрывается само.
И отдельно про имена: два человека под одним именем — это два человека, а
конверт для Bob приходит владельцу ключа, а не тёзке.
